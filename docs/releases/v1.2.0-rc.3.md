# Maverick v1.2.0-rc.3

RC.3 is a full-transport candidate, not a published GitHub
release or Stable qualification. Field testing, real deployment and publication
remain deferred. Use SOURCE.txt to identify the exact checked candidate commit.

## Scope

- Full candidate binaries include H2 and H3. Both carry TCP and persistent UDP
  sessions; H3 uses native datagrams, H2 reliable compatibility.
- Newly generated direct configurations select a dual server and an automatic
  client with explicit `allow_reliable` UDP policy. `--h2`, `--quiche-h3` and
  `--udp-policy native_required` retain clear manual choices. Existing omitted
  settings keep their meaning; files are not rewritten or overwritten.
- New sessions share core-owned reachability avoidance/retry. Only eligible
  pre-response H3 network failure, or authenticated missing UDP capability under
  the compatible policy, can select H2 before data. Identity, authentication,
  protocol, target and admission failures never authorize fallback. Sessions
  never migrate and application packets are not automatically replayed.
- H2 UDP retains a connected target socket/source port and supports continuous
  upload, independent replies, idle/control/drop cleanup and bounded resources.
  The public SDK exposes the same selected session API as the official client.
- Protected H2 intermediaries use independently verified inner TLS; new relay
  generation requires origin identity. TLS-terminating H3 fronting is unsupported.
- CLI stop signals, a Linux service template, SDK/wire documentation and checked
  control-frame examples support integration and later deployment preparation.

## Compatibility and limits

Runnable YAML and authentication versions remain v1 and v1/v2 respectively.
The explicit UDP policy requires authenticated capability bit 62. Reliable
fixed-target UDP uses OpenUdp/UdpPacket flags 2; legacy flags 0 retain their
request/response behavior. Older peers without the capability are rejected for
new-policy sessions; no silent downgrade to the old exchange format occurs.
Profile URI v1 and policy-only Config v2 projection reject settings they cannot
preserve. Full YAML and stored SDK profiles retain the UDP policy.

Native UDP payloads are at most 1200 bytes; reliable H2 payloads at most 65507.
SOCKS headers and actual path limits may reduce these sizes. Queues are bounded,
oversized/full-queue packets may drop, and no fragmentation/reassembly is added.
Replies are restricted to each connected target; arbitrary unsolicited ingress
and SOCKS fragmentation are outside this implementation. H2 reliability may
increase latency under loss. No universal application compatibility is claimed.

Performance-based route ranking is frozen. Active-session migration is excluded
permanently. H3 does not support the built-in local DNS listener or TUN; callers
can carry DNS as application UDP through the normal session API. No browser
equivalence, anonymity or broad censorship-resistance claim is made.

## Verification and rollback

The candidate must pass the complete applicable local/CI product, rustls, H3,
retained candidate, security, dependency, native artifact/SBOM and upgrade/
rollback gates. Native artifact checks exercise TCP and persistent UDP through
both H2 and H3. Final evidence must identify the exact source and archive bytes;
earlier RC.2 or baseline results do not qualify this candidate.

The fixed compatibility rollback partner remains immutable `v1.2.0-beta.4`.
Preserve a matched old binary and old configuration/profile backup. New UDP,
protection and H3 settings cannot be silently discarded to make an old binary
accept them. Native compatibility drills do not substitute for the deferred
owner-controlled field rollback. Existing published releases remain unchanged.
