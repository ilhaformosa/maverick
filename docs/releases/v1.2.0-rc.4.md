# Maverick v1.2.0-rc.4

RC.4 replaces the reviewed RC.3 candidate with two resource-control fixes.
It is a candidate, not a public release or Stable qualification. Field use,
real deployment and publication remain deferred. Identify each archive by its
SOURCE.txt revision and checksum; original RC.3 evidence and files remain intact.

- H2/H3 dual listeners now reserve the existing shared global/source connection
  allowance before QUIC/TLS allocation and retain it for the transport lifetime.
  Pending H3 handshakes cannot bypass capacity already occupied by H2, or vice
  versa. Existing pre-authentication limits and deadlines remain.
- Canceling reliable UDP graceful close retains task ownership until the
  existing Drop cleanup can abort it. A stalled response no longer leaves an
  H2 stream behind after caller cancellation. Normal close and timeout behavior
  remain covered.

The [RC.3 security review](../RC3_SECURITY_REVIEW.md) records scope, findings
and evidence limits. Regression tests reproduce both issues on RC.3 and cover
the fixed paths, both arrival orders, global/source limits, normal forwarding,
pending-handshake expiry, UDP cancellation and ordinary close timeout.

H2/H3 TCP/UDP support, UDP policy, generated dual/auto defaults, protected H2,
configuration/wire/auth versions, payload limits and unsupported routes remain
as described in [RC.3](v1.2.0-rc.3.md). No performance scoring, active-session
migration, new dependencies or new relay architecture is introduced.

All applicable product, rustls, H3, retained candidate, security, dependency,
artifact/SBOM and fixed Beta.4 upgrade/rollback checks remain required. Full
packages include H2/H3; verification retains the RC.3 and older artifact profiles.
Qualification belongs to the exact replacement revision and bytes, not the
earlier candidate's passing checks.
