# Maverick v1.2.0-rc.6

RC.6 is an unpublished maintenance candidate following the Rust 1.100.0
migration. It retains the frozen H2/H3 TCP/UDP, new-session selection, UDP
policy, SDK and origin-protected H2 feature scope. Published RC.5 remains fixed
at `e4a21e2`; neither its files nor its field qualification are changed.

Active runtime/test dependencies, security and SBOM tools, pinned workflow
actions and the separately dated fuzz toolchain are updated. Ordinary builds
remain pinned to Rust 1.100.0. The quiche 0.30.1 dependency contract requires
libc below 0.2.190, so RC.6 uses compatible 0.2.189 rather than overriding
upstream constraints. The retained quiche 0.29.3 comparison and fixed Beta.4
rollback inputs remain historical baselines.

serde-saphyr remains at 1.3.0: the 2.x null-to-empty behavior change breaks the
documented configuration contract and two existing compatibility regressions.
No compatibility conversion layer or silent configuration migration is added.

The fuzz lockfile is synchronized with the current source; CI checks it with
`--locked` and rejects dependency-lock mutation after bounded fuzzing. Its
isolated dependency graph also joins the existing supply-chain checks.
The existing fuzz engine's NCSA license is reviewed and allowed only for
libfuzzer-sys 0.4.13; the fuzz harness declares the repository's Apache-2.0
license. Unused direct tracing dependencies are removed. The fixture's Brotli
dependency remains necessary for shared browser TLS source, and the quiche log
dependency restricts compiled log levels.

BoringSSL
5.5 rejects the known distrusted keys before Maverick's callback; regression
tests cover both rejection layers and the valid-chain control. Source-bound
SBOM tool identity preserves validation of older published dependency lists
while new candidate generation uses cargo-cyclonedx 0.5.10.

Full review, compatibility, local/CI, security/dependency, fuzz, native package,
SBOM and upgrade/rollback results belong to the exact candidate's delivery
record. This source preparation does not yet claim those gates are complete.
Any concrete review findings and their dispositions must be recorded before
candidate qualification.

Field testing, real deployment, resource creation, public release tags and
Stable publication remain deferred. No performance-ranking framework,
active-session migration or new intermediary/cryptographic architecture is
introduced.
