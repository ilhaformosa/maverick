# Maverick v1.2.0

Maverick 1.2.0 is the stable release of the experimental Rust privacy proxy.
The maintainer deferred field acceptance for this release. Real-network use,
interoperability with a deployed intermediary, operational rollback and the
planned 72-hour soak remain unverified. Field testing may resume in a later
evaluation. Maverick makes no claim of production readiness, anonymity,
censorship resistance or browser equivalence.

## Downloads and setup

Choose the files for your platform from the assets below.

| Platform | Archive |
|---|---|
| Apple Silicon macOS | `maverick-1.2.0-pilot-aarch64-apple-darwin.tar.gz` |
| Linux x86_64 | `maverick-1.2.0-pilot-x86_64-unknown-linux-gnu.tar.gz` |

Each archive has a matching `.tar.gz.sha256` checksum and a CycloneDX
software bill of materials (`.cdx.json`). Verify the archive checksum before
extraction, then follow `START_HERE.txt`. For an upgrade, back up the previous
binary and its private configuration together. The matching SDK is available
from source. [Installation guide](https://github.com/ilhaformosa/maverick/blob/v1.2.0/docs/DEPLOYMENT.md)
and [Rust SDK guide](https://github.com/ilhaformosa/maverick/blob/v1.2.0/docs/INTEGRATION.md).

## Included in 1.2.0

- The CLI and Rust SDK carry TCP and UDP over direct H2 and H3 connections.
  New direct configurations prefer H3. With the default `allow_reliable`
  policy, new UDP sessions can use reliable H2 after an eligible H3 setup
  failure. Choose `native_required` to require native H3 datagrams.
- An H2 intermediary that terminates outer TLS can carry a separate,
  authenticated TLS connection to the origin for TCP and reliable UDP.
  Generate this configuration with `gen-config --relay` and verify the origin
  identity independently. TLS-terminating intermediary H3 is unsupported.
  Legacy intermediary H2 and WebSocket modes expose tunnel contents to the
  intermediary and are excluded from the stable route set.
- Existing YAML files that omit the new transport settings retain their
  previous behavior. The source feature for H3 is still named
  `experimental-h3`. [Configuration reference](https://github.com/ilhaformosa/maverick/blob/v1.2.0/CONFIG.md).

## Fixes since RC.6

- Clients connecting to a local SOCKS5 listener on IPv6 can now use UDP.
- The HTTP CONNECT listener enforces its 8 KiB header limit even when the
  application sends tunnel data in the same read.
- Local CLI self-checks keep temporary TLS private keys owner-readable on
  Unix and outside the directory that serves fallback pages. The local
  benchmark also handles larger echo transfers.
- Configuration checks reject credential IDs above the protocol's 512-byte
  limit and detect duplicate active or previous IDs across server users.
  `gen-user` preserves special characters in names. `gen-config` checks both
  output names for existing files or links before writing the pair.
- H2-only server configurations now require enough pre-authentication slots
  for a connection. Direct H2 requires two, and origin-protected H2 requires
  three. The default is 512.
- Fallback pages honor HTTP HEAD requests, and reverse-proxy fallback can
  connect to an IPv6 literal upstream. When an integrating client supplies
  initial TCP data with its open request, the server forwards those bytes in
  order after admission.
- The optional TUN engine updates `heapless` to 0.9.4 for reported memory-safety
  issues. This dependency is outside the packaged CLI feature set.

## Verification scope

The release workflow selects the Linux and macOS packages from checks on the
tagged source revision. Those checks exercise TCP and UDP on loopback, verify
package contents and dependency inventories, and rehearse a direct-H2 rollback
using the fixed Beta.4 binary and configuration. The publication workflow
rechecks the six files before uploading them.
