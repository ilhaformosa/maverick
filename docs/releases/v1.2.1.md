# Maverick v1.2.1

Maverick 1.2.1 adds two diagnostics for operators of the experimental TCP
and UDP privacy proxy.

- Add `--explain` to `maverick check-config --kind client -c client.yaml`
  or its server equivalent to see the configured routes and the transports
  compiled into the binary. It runs offline and omits private values.
- Start the SOCKS client with `maverick client -c client.yaml --diagnose-udp`
  to see which carriers the configuration allows, which one admitted a
  session, and whether the client observed a target reply.

Current 1.2.0 configurations retain their meanings. To upgrade, save each
role's executable and private YAML together. Verify the new archive checksum
and its internal checksums, check the working YAML, then restart with the
new executable. To roll back, restore the saved executable and YAML on each
side, restart and verify TCP and UDP transfers. On macOS, stop the running
process, stage the executable in a fresh file in the same directory and
rename it over the live path for both upgrade and rollback.

Choose the archive, its matching SHA-256 checksum and its CycloneDX SBOM for
Apple Silicon macOS (`aarch64-apple-darwin`) or Linux x86_64
(`x86_64-unknown-linux-gnu`). Follow `START_HERE.txt` inside the archive.
The matching Rust SDK is available at this tag.
[Installation](https://github.com/ilhaformosa/maverick/blob/v1.2.1/docs/DEPLOYMENT.md)
and [configuration](https://github.com/ilhaformosa/maverick/blob/v1.2.1/CONFIG.md).

Qualification covers the packaged 1.2.0 and 1.2.1 clients and servers on
loopback across fixed H2, fixed H3, both automatic UDP policies, automatic
fallback to H2 and origin-protected H2. Each route exercises both mixed
versions, the two-sided upgrade and restoration. The separate Beta.4
direct-H2 rollback remains covered. The release workflow publishes the
qualified archives directly from the tagged main commit's CI run.

Real-network application use, provider interoperability, operational
rollback and a 72-hour field soak remain unverified. The project makes no
production-readiness, anonymity, censorship-resistance or browser-equivalence claim.
