# Maverick v1.2.3

Maverick 1.2.3 lets operators check a configuration handoff, certificate
replacement or credential rotation before restarting either peer. Existing
1.2.2 private YAML files can be used with the new executable.

| Before you change | Command | What it checks offline |
|---|---|---|
| Handing off client and server settings | `maverick check-pair --client client.yaml --server server.yaml` | Shared TCP and UDP carriers, origin protection, tunnel path, authentication policy and the selected credential. |
| Scheduling a credential switch | Add `--at 2030-04-01T00:30:00Z` to `check-pair`, substituting the planned time. | Which credential the client selects and whether an enabled server credential accepts it at that instant. Check each side of the switch and the end of the overlap. |
| Restarting a server after renewal | `maverick check-config --kind server -c server.yaml --check-tls` | The configured TLS backends can load the staged certificate chain and matching private key. Run from the service working directory. |
| Updating a protected H2 origin certificate | `maverick check-config --kind client -c client.yaml --origin-cert replacement-chain.pem` | The public chain, with the leaf first, passes the client's inner CA, hostname, validity and leaf-pin checks. Keep the private key at the origin. |

The checks read the supplied files, use fixed diagnostics and return a
nonzero exit status on failure. A fresh connection and target reply confirm
whether the running service transfers traffic. [Configuration reference](https://github.com/ilhaformosa/maverick/blob/v1.2.3/CONFIG.md#validation).

Download the archive, checksum and CycloneDX dependency inventory for Apple
Silicon macOS or native Linux x86_64. Check the SHA-256 checksum and follow
`START_HERE.txt` inside the archive. Save each role's executable and private
YAML together. Stop the process, stage the replacement executable in a fresh
file and rename it into place. Follow the same procedure to restore the saved
program and configuration, then verify TCP and UDP transfers. [Deployment and rollback](https://github.com/ilhaformosa/maverick/blob/v1.2.3/docs/DEPLOYMENT.md).

The first 1.2.3 candidate passed all 21 packaged CLI configuration tests on
each native platform. Each also passed 30/30 TCP and UDP cases against
published 1.2.2, including each mixed client/server direction, two-sided
upgrade and restoration of the saved programs and private configurations.
The 1.2.0, 1.2.1 and separate Beta.4 compatibility drills also passed.
[Native macOS results](https://github.com/ilhaformosa/maverick/actions/runs/45881026669/job/140120144192)
and [native Linux results](https://github.com/ilhaformosa/maverick/actions/runs/45881026669/job/140120143846).
The published files come from the independently qualified tagged main revision.

Maverick remains experimental. Real-network application use, provider
interoperability, deployment rollback and a 72-hour field soak remain unverified.
